## Build mandate
Every page ships as a complete, professional product surface: real product-specific copy, a considered layout with hierarchy, all states (empty, loading, error), and enough supporting context that a number is never presented without knowing what it means. Never a lone stat floating on an empty page.

## Character & direction
Dark and focused. Near-black canvas (`#0A0F14`), one accent (`#38BDF8`, a clear sky blue - read as "signal" against the dark neutrals, never decorative). Low chrome: hairline borders over shadows, no gradients, no illustration. The console is dark-only by design (a deliberate identity choice for an ops/security tool, not an unfinished light mode) - stated here explicitly so it reads as intentional, not an oversight.

## Composition patterns
5.1 is a single page: a header (product name + page title), a stat-tile row (2 tiles today: Total requests, Blocked), then a two-column chart section (findings by category; requests over time) that stacks to one column on narrow screens.

5.2 added the console's nav shell: a top-level header (brand + `Dashboard`/`Workloads` nav links, active link on a `--color-surface` pill, `aria-current="page"` via React Router's `NavLink`) that every page renders under, plus a shared footer rendered once below the routed page rather than per page. Each page keeps its own page-level title bar directly under the shell header (page title, page-specific actions like "Refresh" or "New workload" on the right).

5.2's Workloads page is a list/table screen: title + one-line supporting copy explaining the fallback-to-default behavior, a primary "New workload" action (the one place besides chart marks that uses a solid `--color-accent` fill with `--color-on-accent` text - reserved for the page's single primary action, not repeated elsewhere), then a table (workload name-or-truncated-id, policy profile and fail mode as bordered pill badges, budgets, created date, a per-row "Edit" action). Create and edit share one form, opened in a native `<dialog>` (`showModal()`) centered over a dimmed backdrop (`--color-canvas` at 80% opacity) - chosen over a hand-rolled overlay since the native element gives correct focus-trap/Escape/focus-return behavior for free.

5.3 added the console's first list-then-detail pair, sharing a new `displayId(id, name?)` helper (`src/lib/format.ts`, extracted from Workloads.tsx's own inline copy) rather than duplicating the truncated-id fallback logic a third time. The Sessions list follows the same title-plus-table shape as Workloads, with a "jump to a session" text input + Go button next to the title instead of a primary action button (there's no create/edit concept for a session). Table columns: session id (always truncated, sessions carry no name), workload (name-or-truncated-id), an "Escalated" pill (`--color-error` border/text, shown only when true - a dash otherwise, so a clean session doesn't compete visually with a genuinely escalated one), cumulative risk, a strikes summary (nonzero categories only, e.g. "pii ×1", em dash if none), execution count, and last activity (derived by subtracting the ledger's 15-minute TTL back out of `ttl_expires_at`, since no separate last-activity field exists). The detail page (`/sessions/:sessionId`) composes top to bottom: a back link, session id + workload + created date, an escalation banner (same `--color-error` treatment as the pill, but a full sentence explaining the accumulation-not-single-turn caveat - never color-only) shown only when escalated, a ledger summary card (cumulative risk and execution count as large stat numbers, then all six strike categories always rendered as pill badges so the reader can see which categories are at zero, not just which are elevated - the elevated ones get the same `--color-error` treatment as the escalated pill), then a chronological list of execution cards (turn number, a Blocked/Clean pill using `--color-error`/`--color-success`, tokens/latency, and each finding as a row: category, confidence, evaluator tier, and request/response side from `evidence_ref.side`). A 404 renders a dedicated "Session not found" card, not the generic error state, so a mistyped jump-to-session id reads as a correctable mistake rather than a broken page.

5.4 added the console's first auto-refreshing page. Live Feed is a title-plus-table page like Sessions, but the title row's right-hand action is a Pause/Resume toggle instead of a primary button, with a "Paused" pill (bordered, `--color-muted`, matching the Escalated pill's shape but neutral rather than alarming) appearing next to it only while paused. The table (time, session, workload, a Blocked/Clean pill reusing SessionDetail's `BlockedBadge` styling, category pills, tokens, latency) polls every ~3s in the background; on background refresh failures the existing table stays on screen with a small muted status line above it rather than swapping to the generic error state - only the very first load can show that. A row that just arrived gets a 1 second `border-l-2 border-l-accent` plus a faint accent background tint that fades via `transition-colors duration-1000`, then reverts to a normal row - signals "new" without a jarring reflow or a toast/notification pattern this design system doesn't otherwise use. Session cells link into the existing `/sessions/:sessionId` detail page via React Router's `Link` (not a plain anchor, to stay a client side transition), reusing 5.3's page rather than building a second drilldown view.

8.2 replaced the Blocked/Clean `BlockedBadge` (previously duplicated identically in `LiveFeed.tsx` and `SessionDetail.tsx`) with a shared `DispositionBadge` (`src/components/DispositionBadge.tsx`) rendering three states instead of two: Clean (`--color-success`, unchanged), Flagged (new `--color-warning` amber token - a `fast`-profile workload's cheap-tier hit that released instead of blocking), Blocked (`--color-error`, unchanged). Same pill shape/sizing as before; only the state count and the shared location changed.

## Component & usage rules (do's and don'ts)
- Accent (`--color-accent`) marks the one thing that matters per surface: the "Blocked" tile's number, chart bars/lines. Never used for backgrounds or body text.
- Cards (`--color-surface`) get a single hairline border (`--color-border`), never a shadow - shadows read as "light UI" and fight the near-black canvas.
- A tile's supporting caveat text (e.g. the blocked-count limitation) is `--color-muted`, never smaller than 14px, never color-only - it's always a full sentence, not a bare icon.
- Numbers are the loudest element on a tile (`--text-3xl`, `--color-ink`); their label is quiet (`--text-sm`, `--color-muted`) above them.

## Responsive & accessibility direction
Stat tiles: 2-up on desktop, stack to 1-up under 640px. Charts: side by side above 1024px, stacked below. Every chart has a text-based fallback summary (a visually-hidden table-like readout) so the data isn't color/shape-only for assistive tech - Recharts' SVG output alone doesn't satisfy this.
