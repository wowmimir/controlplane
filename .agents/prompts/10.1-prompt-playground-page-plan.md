# 10.1. Prompt Playground Page

**Date**: 2026-08-27
**Status**: Accepted

## Summary

A new console page at `/playground`: a prompt textarea + Send button that calls
`POST /v1/chat/completions` directly from the browser, against a **selectable workload** and
an **editable model**. It renders the model reply, or — for a `4xx`/`5xx` — the block,
escalation, or error reason pulled from the OpenAI-style `{"error": {...}}` envelope. It
captures the `X-Session-Id` response header and threads it (plus the full running transcript)
into every subsequent send, so consecutive messages in the box behave as one real
conversation. That continuity is the point: it makes ControlPlane's multi-turn escalation
feature demoable by **typing live**, not by running a pre-threaded script.

One backend change is required (see Context): `expose_headers` on the CORS middleware.
No new route, no schema change, no new dependency.

## Context

`STATUS.md` Phase 10 (added 2026-08-27, ratified in the same day's handoff note) locks the
demo UI as a **hybrid**: this playground page for live-typed simple demos (clean pass, instant
cheap-tier block, ad-hoc/audience prompts), while `scripts/seed_demo.py` +
`docs/demo-script.md` keep the two scenarios too precise to type on stage (the two-turn
escalation with a threaded session id, and the async hallucination finding with its
provably-wrong math prompt). 10.1 builds the page; 10.2 is a no-code presenter decision that
updates the shot list afterwards.

**Why this is buildable now.** Everything the page calls already exists:

- `POST /v1/chat/completions` (`app/routers/chat.py`) is already OpenAI-shaped
  (`app/schemas/chat.py` — `{model, messages}` in, `{id, object, created, model, choices,
  usage}` out) and already sets `X-Session-Id` / `X-Workload-Id` response headers on **every**
  return path, blocks included: the success return (`chat.py:89-90`), the request-side block
  (`:116-117`), the `502` model-failure path (`:161-162`), and the response-side block
  (`:233-234`).
- `_resolve_session` (`chat.py:288`) creates a real `Session` row for a first message (even a
  blocked one), so the id handed back on a blocked turn is valid and reusable. It returns
  `400` if a session id is reused under a **different** workload (`forks.md` Fork #1: a session
  cannot span two workloads) — which is why changing the workload in the UI must reset the
  stored session id.
- The four block/error envelopes the page must render are all built and stable:
  `_policy_block_response` (`403`, `type: "controlplane_policy_violation"`, `code` = the
  triggering category), `_escalation_block_response` (`403`,
  `type: "controlplane_session_escalated"`, `code: "session_escalated"`),
  `_model_error_response` (`502`, `type: "controlplane_upstream_error"`), and
  `_internal_error_response` (`503`, `type: "controlplane_internal_error"`).
- **8.0 is the prerequisite.** It fixed request-side full-history rescan — request-side cheap
  tier now scans only `messages[-1].content`, not the joined history. Without that, a
  playground that resends the whole conversation each turn (what any real OpenAI-shaped client
  does) would re-trigger an old PII/injection message as a fresh content violation on every
  later turn, and the "a clean turn blocked purely on accumulated history" demo would be
  unreachable. `STATUS.md`'s 8.0 line calls this dependency out explicitly.

**Console shape** (what the page copies): dark-only React + React Router + Tailwind v4 design
tokens (`console/src/index.css`). Every page is a header bar (`border-b`, `h1` +
description) followed by a `mx-auto max-w-6xl` `<main>` — `console/src/LiveFeed.tsx` is the
closest reference (it also does the load / error / ready state split and a "Pause" style
control). API calls live in `console/src/api.ts` behind `API_BASE_URL`
(`VITE_API_BASE_URL ?? 'http://localhost:8000'`); `parseOrThrow` there **throws** on any
non-2xx. Types mirror the backend in `console/src/types.ts`. `displayId(id, name?)` in
`console/src/lib/format.ts` shortens ids. Nav links + `<Route>`s are all in
`console/src/App.tsx` (6 pages today: Dashboard, Workloads, Sessions, Review, Detection
Health, Live Feed).

### The one backend change: `expose_headers`

`STATUS.md`'s 10.1 line says *"No backend changes needed — the endpoint is already
OpenAI-shaped and CORS already allows POST from the console's origin"*. That is **wrong on one
point**. Allowing the POST *method* is not the same as exposing response *headers*. Browsers
hide every response header from cross-origin `fetch` JS except a small safelist unless the
server sends `Access-Control-Expose-Headers`. `app/main.py`'s `CORSMiddleware` sets no
`expose_headers`, so `response.headers.get('X-Session-Id')` in the console returns `null`
today, and the multi-turn threading requirement fails silently.

**Fix:** add `expose_headers=["X-Session-Id", "X-Workload-Id"]` to the middleware. One line,
reversible, no behaviour change for any existing caller (the Python `httpx` clients in
`scripts/*` never needed CORS). Recorded below as an **Assumed decision** correcting the
`STATUS.md` note, per `AGENTS.md` Rule 9.

### Confirmed / settled with the user before this spec

1. **Keep the playground thin.** It classifies an outcome by HTTP status + `error.type`
   **only**. A `200` is shown as "allowed" with no attempt to distinguish `clean` vs a
   `fast`-profile `flagged` release vs a `balanced` `redacted` release — the OpenAI response
   body carries no disposition, and adding an `X-ControlPlane-Disposition` header was
   considered and **declined** for this milestone (deferred, see Follow-up). A `redacted`
   release is still visible through the `[REDACTED:<category>]` text already substituted into
   the content. The flag/redact-per-profile contrast stays a Live Feed / Session Detail /
   `scripts/simulate_use_cases.py` story.
2. **Workload selector + model field.** A `<select>` populated from
   `GET /api/console/workloads`, each option labelled by `metadata.name` (falling back to a
   short id), with a first option "Default workload" that sends **no** `X-Workload-Id`. Plus
   an editable model `<input type="text">` prefilled from a constant
   `DEFAULT_PLAYGROUND_MODEL = "minimax-m3:cloud"` (the confirmed-working Ollama tag per
   `decisions.md`, 2026-08-23). The model is a free field, not derived from the workload — a
   `Workload` row stores no model.

- **AC-1** — `app/main.py`'s `CORSMiddleware` gains `expose_headers=["X-Session-Id",
  "X-Workload-Id"]`. Verified by reading `X-Session-Id` off a `fetch` response in the browser

- **AC-2** — `console/src/App.tsx` has a new "Playground" nav link and
  `<Route path="/playground" element={<Playground />} />`.
- **AC-3** — The page renders: a workload `<select>` (options from `fetchWorkloads()`; first
  option "Default workload" = no id); a model `<input type="text">` prefilled with
  `DEFAULT_PLAYGROUND_MODEL`; a prompt `<textarea>`; a Send button (disabled while a request
  is in flight **or** the prompt is blank); and a "New conversation" reset button.
- **AC-4** — Send issues `POST ${API_BASE_URL}/v1/chat/completions` with body
  `{ model, messages }` where `messages` is the **full running transcript** — every prior
  user and assistant turn plus the new user message, each `{role, content}`. `X-Workload-Id`
  is sent only when a non-default workload is selected; `X-Session-Id` is sent only once the
  page has learned one.
- **AC-5** — On `200`: `choices[0].message.content` is appended to the transcript as an
  `assistant` turn and rendered; `X-Session-Id` is read from the response and stored for the
  next send.
- **AC-6** — On `403` with `error.type === "controlplane_policy_violation"`: an outcome panel
  shows "Blocked", `error.message`, and `error.code` (the category). The user's message stays
  in the transcript; **no** assistant turn is appended; `X-Session-Id` is still captured.
- **AC-7** — On `403` with `error.type === "controlplane_session_escalated"`: a visually
  distinct outcome panel shows "Session blocked — accumulated risk" and `error.message`. The
  user's message stays in the transcript; no assistant turn; session id still captured.
- **AC-8** — On `502` / `503` / a thrown network error: an outcome panel shows `error.message`
  (or a generic fallback string if the body is unparseable). The page stays usable. *(Built:
  the attempted user message is kept visible above the error panel rather than removed, and
  its text is restored to the textbox for an easy retry — a `502`/`503` did reach the proxy,
  so hiding the turn is more confusing than showing it. Logged in `decisions.md`.)*
- **AC-9** — Changing the **workload**, or pressing "New conversation", clears **both** the
  stored `X-Session-Id` and the transcript. (Mandatory: `_resolve_session` returns `400` if a
  session id is reused under a different workload.) *(Built: changing the **model** field does
  NOT reset — its `onChange` fires per keystroke, which would wipe the transcript mid-typing,
  and the proxy has no model-based session constraint. Logged in `decisions.md`.)*
- **AC-10** — When a session id is set, it is shown shortened via `displayId`, linking to
  `/sessions/{sessionId}` so the presenter can open the drilldown.
- **AC-11** — `npx tsc -b` and `npm run build` in `console/` complete clean.

## Decision

### Backend (`app/main.py`)

Add one kwarg to the existing middleware call:

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_methods=["GET", "POST", "PATCH"],
    allow_headers=["*"],
    expose_headers=["X-Workload-Id", "X-Session-Id"],   # 10.1
)
```

Nothing else in `app/` changes. No `X-ControlPlane-Disposition` header (declined — see
Confirmed #1). The four `_*_response` builders and every `response.headers[...]` line in
`chat.py` are already correct and are **not touched**.

### Frontend

**`console/src/types.ts`** — add:

```ts
export interface ChatTurn {
  role: 'user' | 'assistant'
  content: string
}

// 10.1: the outcome of one /v1/chat/completions call, already classified by
// HTTP status + error.type so the page never re-inspects the raw response.
export type ChatResult =
  | { kind: 'ok'; content: string; sessionId: string | null }
  | { kind: 'blocked'; message: string; code: string; sessionId: string | null }
  | { kind: 'escalated'; message: string; sessionId: string | null }
  | { kind: 'error'; message: string }

export const DEFAULT_PLAYGROUND_MODEL = 'minimax-m3:cloud'
```

**`console/src/api.ts`** — add a **non-throwing** sender (unlike `parseOrThrow`, the page
needs the `4xx`/`5xx` body):

```ts
export async function sendChatCompletion(params: {
  model: string
  messages: ChatTurn[]
  workloadId?: string | null
  sessionId?: string | null
}): Promise<ChatResult> {
  const headers: Record<string, string> = { 'Content-Type': 'application/json' }
  if (params.workloadId) headers['X-Workload-Id'] = params.workloadId
  if (params.sessionId) headers['X-Session-Id'] = params.sessionId

  let response: Response
  try {
    response = await fetch(`${API_BASE_URL}/v1/chat/completions`, {
      method: 'POST',
      headers,
      body: JSON.stringify({ model: params.model, messages: params.messages }),
    })
  } catch {
    return { kind: 'error', message: 'Could not reach ControlPlane.' }
  }

  const sessionId = response.headers.get('X-Session-Id')
  const body = await response.json().catch(() => null)

  if (response.ok) {
    const content = body?.choices?.[0]?.message?.content ?? ''
    return { kind: 'ok', content, sessionId }
  }

  const err = body?.error ?? {}
  const message = err.message ?? `ControlPlane returned ${response.status}.`
  if (response.status === 403 && err.type === 'controlplane_session_escalated') {
    return { kind: 'escalated', message, sessionId }
  }
  if (response.status === 403) {
    return { kind: 'blocked', message, code: err.code ?? 'policy_violation', sessionId }
  }
  return { kind: 'error', message }
}
```

(`ChatTurn` import added to `api.ts`'s type import block.)

user turn into `transcript` immediately; `setPrompt('')`, `setPending(true)`,

still capture `result.sessionId`; on `error` set `outcome` only. `finally` `setPending(false)`.

`setTranscript([])`, `setOutcome(null)`.

### Why full-history resend (not just the latest message)

Deliberate, and consistent with 8.0's fix. Sending the whole transcript each turn is what a
real OpenAI client does, and it is what lets the escalation demo work: a violating message
stays in the transcript, but because request-side cheap tier scans only `messages[-1]`
(8.0), it does **not** re-block on later clean turns — it still drove a strike / risk bump on
the turn it was sent, and that accumulated state is what trips
`_escalation_block_response` on a subsequent clean prompt. Scanning only the latest message
also keeps a long benign conversation from being re-scanned in full on every turn.

## Consequences

- A `fast`-profile `flagged` release is indistinguishable from a clean pass in this UI, by
  design. The fast-profile flag demo stays on the Live Feed / Session Detail. `docs/demo-script.md`
  (updated in 10.2) should not point the flag shot at the playground.
- `expose_headers` makes two header **names** (already set as headers on every response, blocks
  included) readable by the
  origins in `allow_origins` — localhost:5173 only today. No security impact; no new data is
  disclosed.
- Every clean send makes a real model call — same cost/latency as any other proxy request.
  Fine against local Ollama; a slow cloud-tag model (e.g. `nemotron-3-ultra:cloud` at ~50s)
  would make the page feel stuck, so the default stays `minimax-m3:cloud`.
- Streaming stays out of scope (`forks.md` Fork #4/#5) — the page shows the full buffered
  reply only, after the whole governance pipeline has run.
- The page has no auth, same as the rest of the console and the proxy
  (`decisions.md`, 2026-08-23 — caller-asserted headers, accepted for the MVP).
